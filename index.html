本 repo 的教材編排、PR 提交機制、AI 審查設計，不是憑空想像，而是參考了以下國際上已有實證基礎的方法。整理這頁的目的，是讓有興趣參考這套做法的老師，能同時看到「我們做了什麼」跟「這麼做的依據是什麼」，方便評估是否適合自己的課程。

Git-based 作業提交系統的實測效益

來源：Improving Assignment Submission in Higher Education through a Git-Enabled System: An Iterative Case Study（2025，arXiv）

研究實測比較 Git 版本紀錄批改 vs. 傳統批改，發現利用 commit 歷程批改可節省約 38% 的批改時間，並能透過 commit 時間戳記識別最後一刻趕工的提交、比對版本歷程協助判斷是否為抄襲。

💡 本 repo 對應：我們用 PR 的 commit 歷程跟 Actions 排程審查，方向與此研究一致；commit 時間分布這個資料維度目前還沒有利用，是可以擴充的方向。

延伸詮釋（非論文原文，是把論文核心價值套進法律教育的引申）：論文強調 commit 歷程能強化「instructor oversight」，換句話說，老師看到的不再只是學生繳交的最終「答案」，而是這個答案怎麼一路修改出來的「歷程」。這個角度移植到法律教育，可以理解成一種「法律論證形成史」——學生第一次補完寫了什麼、之後查證條文後怎麼改、跟同學討論後又怎麼調整，這整條修改軌跡本身就是值得評分參考的學習歷程，不是只有最後交出來的那個版本才算數。

🔗 arxiv.org/html/2510.06363

Case Method 教學創新的系統性回顧（2000–2024）

來源：Innovations in the case method of teaching management, 2000–2024: A scoping review（ScienceDirect, 2025）

分析 84 篇案例教學創新論文，歸納出五大驅動力：課堂管理困難、傳統教材不足、學生參與度不足、課程設計挑戰、線上教學挑戰。

💡 本 repo 對應：解決「傳統教材不足」（改用真實新聞案例而非死板判決書）與「學生參與度不足」（用 PR 互動取代單向繳交）這兩項，是這個 repo 最初的設計動機。

🔗 sciencedirect.com/science/article/pii/S1472811725000205

結構化任務提升案例教學學習效果

來源：The efficacy of the case method in tertiary business education: A scoping review: 2000-2022（ScienceDirect, 2024）

回顧研究指出：案例任務的結構化程度越高（給予明確的分析架構與引導），學生在知識掌握、批判思考、課堂參與、團隊合作、決策能力等面向的學習效果越好。

💡 本 repo 對應：講義框架裡的「引導提問」「範例句型」「補完步驟建議」「進度統計」，都是把這個結構化原則落實成具體介面設計。

🔗 sciencedirect.com/science/article/pii/S1472811724000545

Role-play 作為正式的案例教學類型

來源：National Center for Case Study Teaching in Science, SUNY-Buffalo（案例類型與教學方法分類）

該機構把案例教學的「方法」正式分類為 PBL、辯論、jigsaw 拼圖法、role-play（角色扮演）、公聽會模擬等類型，role-play 是其中被廣泛採用、有教學實績的正式類型之一。

💡 本 repo 對應：「換你當事人」這個區塊（要求學生假設自己是案例中某一方的決策者，提出自己的策略），採用的就是 role-play 這個正式教學類型，不是隨意設計的花招。

🔗 sciencecases.lib.buffalo.edu（經 Columbia CTL 案例教學資源頁引用確認）

Feedback Pull Requests（GitHub Classroom）

來源：GitHub Education 官方文件

GitHub 為教學情境設計的內建機制：學生接受作業後，系統自動開一個 PR 供老師逐行留言回饋，並內建「GitHub 帳號 ↔ 真實姓名」名冊對應功能。

💡 本 repo 對應：我們的 PR 提交流程是手動搭建的簡化版，若未來要擴大規模，GitHub Classroom 的名冊功能可以取代目前手動維護對照表的做法。

蘇格拉底法在法學教育之定位與實證

來源：The Socratic Method，UW Law Digital Commons（Porter 對《Educating Lawyers》與《Best Practices for Legal Education》的批判性回應）

【蘇格拉底法的優勢認可】美國主流法學教育報告肯定蘇格拉底法是「易於規模化、能有效促進主動學習」的教學工具，尤其適合大班 doctrinal 課程。

【既有批評與其局限】但學界批評蘇格拉底法容易讓教師凌駕於學生、造成不尊重的課堂氛圍。現有回應卻止於消極設定：《Best Practices》僅提「不要故意羞辱學生」，這道門檻反而暴露出學界對這套方法的深刻懷疑——「避免羞辱」和「打造投入的課堂」根本是兩回事。

【關鍵突破：課堂共同體】Porter 的答案是：真正的問題不在蘇格拉底法本身，而在於課堂文化。成功的蘇格拉底課堂必須具備「同儕性（collegial）與風險承擔精神（risk-taking）」——讓學生信任彼此的貢獻與思考，而不只信任教師的講述。這樣才能激發蘇格拉底法的核心優勢。

【組織與自發性的張力】然而，「蘇格拉底法失敗」不一定表示這套方法本身有問題；許多失敗的課堂背後是組織不足——教師沒有清楚的學習目標或課堂結構。但 Porter 同時警告：過度的組織與規劃也會扼殺課堂的自發性與即興性。蘇格拉底式教學需要在「精心設計」與「開放探索」之間取得平衡。課堂討論應該是合作的、開放的，充滿意外發現的可能性，以及即將有所發現時的那股活力——它應該成為一種「如何共同思考」的典範。

💡 本 repo 對應：呼應「課堂共同體」與「組織──自發性平衡」原則——中工案例透過清晰的講解結構維持組織性，中信金案例設定明確的 PR 提問框架，同時保留學生共筆中的開放討論空間，把蘇格拉底法的核心精神（引導提問、逐步逼近答案）嵌入同儕互動中，建立「相互尊重、願意冒險表達」的課堂文化。

🔗 digitalcommons.law.uw.edu

蘇格拉底法的批判性觀點（平衡查證）

來源：The Socratic Method Is Not Optimal for Law Student Learning，Loyola University Chicago School of Law

整理反對意見，包括實務律師認為蘇格拉底法訓練出來的是「像法官一樣思考」而非「像律師一樣思考」，對實務準備度的幫助有限；也提及對抗式提問對學生造成的心理壓力等批評。

💡 本 repo 對應：納入這項批評作為設計參考——採用 PR 共筆與情境案例取代對抗式課堂質詢，希望保留蘇格拉底法「逐步引導推理」的優點，同時降低單向質詢對學生造成的壓力。

🔗 luc.edu（Loyola University Chicago）

AI 與結構化引導式對話的技術可行性

來源：IntelliChain: An Integrated Framework for Enhanced Socratic Method Dialogue with LLMs and Knowledge Graphs（arXiv, 2025；GCCCE 2024會議論文）

研究指出 LLM 應用於教育時，普遍面臨準確性、可靠性、與特定教育內容相關性不足的挑戰；作者提出結合知識圖譜與多智能體系統的解法。查證備註（已訂正）：摘要宣稱此框架經過「empirical research」（實證研究）驗證，但查核第4節內文後發現，所謂「結果」僅是作者用同一道雞兔同籠題目，針對三種系統設定各自描述一段設計理念與示範教學策略（見 Figure 2），全文沒有真實學生受試者、沒有樣本數、沒有任何量化分數或統計檢定，屬於概念性示意而非量化實證，摘要用詞與內文實際內容不符。此外，前言與相關研究回顧全文未提及「Socratic」一詞，參考文獻清單也未包含蘇格拉底教學法相關文獻，「Socratic」一詞僅用於描述其結構化引導式對話形式。引用時應嚴格侷限於「AI技術設計理念可行」此一面向，不可作為「AI輔助蘇格拉底教學法有實證效果」的佐證。

💡 本 repo 對應：本 repo 的 PR 審查機制與 news-fact-check 查證方法論，回應的正是此文獻指出的同一個痛點（LLM 生成內容的準確性與可信度），只是解法不同——用人工審查搭配一手來源查證，取代知識圖譜。

🔗 arxiv.org/pdf/2502.00010
